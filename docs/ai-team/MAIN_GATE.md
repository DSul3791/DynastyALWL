### Main gate jobs (slimmed 22 Nov 2026; from the gate after the Z2 run)
Each check runs once, on the machine it needs. Fresh import on both machines (their other jobs need it).
- **Lane B (Linux):** validators (`local_check.sh`: item validator, warnings, island table; look names run in the cloud `merge_check.py`); the slow lane (`--slow`, all four); terrain/starter-cache checks; server smokes (`dedicated_stop_smoke.sh` 2 runs, `play_stop_smoke.sh`, `join_password_smoke.sh`, the `--dedicated` admin check).
- **Lane A (Dave's PC, Windows):** the fast and timing tests (`tests_for_diff.py origin/main <Y> --all --no-slow`: Lane B runs the slow lane); local Play and the join/build-refusal smokes; the window session.
- **Pictures:** only looks whose files changed since their last Lane A picture. A picture taken at a PR head counts at the gate when its look files are byte-identical at the candidate; the gate record lists the carried-over pictures and their source SHA.
- **Frame time:** the 3 cold runs at the spawn stay deciding, with the written limits. The hair Low-quality check runs only when hair or avatar files changed since main; the rig frame time (record only) is not a gate job.
- **A red needing a fix:** the fix is reviewed as usual, then only the jobs whose inputs the fix touches run again at the new SHA: its `--wide` plan (not `--all`), pictures for its picture paths, frame time if it changes `src/` or `scenes/` runtime code, the server smokes if it changes `src/stream`, `src/server`, `scenes/terrain_server` or join code, the import if it changes `project.godot`, `addons/` or assets. A docs-only fix reruns nothing. Every other job's result carries over, recorded with its SHA. Two fixes in one gate, or a fix in shared base files (`project.godot`, a hub), rerun the whole gate.
