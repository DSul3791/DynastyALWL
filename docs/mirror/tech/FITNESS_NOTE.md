# Fitness (Items, 2026-10-21, protocol 26)

- What it changes: only how fast exertion RISES during strenuous activity (running, climbing, tool work, heavy loads): rise per second x exp(-fitness x 0.05). Fitness +10 = 61 percent of the normal rise (winded about 1.65x later), -10 = 165 percent. Recovery, thresholds, speeds are untouched. The old exertion.json "fitness" threshold placeholder stays 1.0.
- Range: whole number -10..+10 (same style as luck), 0 = average adult. New characters start at 0; old characters.json entries without it read as 0.
- Training (Dave 2 Nov 2026, reworked 4 Nov for BUG-023): grows slowly from any effort above 0.1, server-side in `_train_fitness`, saved as `train` in characters.json. Each 10 s tick gives 1 + 2 x effort XP (1 at the line, 2 walking, 3 running) into the day's bucket (`xp_today`, saved); at game midnight the bucket is paid out (message "Your day's work has made you fitter"), or at the next tick after login if midnight passed while away (one bucket only). 1,000 XP is a point, the same at every level; up to +10 above the base. Walking alone is about 14 h from 0 to +10, running about 9 h, a mixed hour about 15 h. Effort between 0.02 and 0.1 neither earns nor costs. Only effort under 0.02 for more than 10 minutes loses a point, one per 12 h, never below the base. All numbers in fitness.json `train`.
- (old) Fixed or growing: fixed for now. server_items.set_fitness(peer, value) is the training hook (clamped, saved, resent to the client); how work trains it is not designed. All numbers in data/items/fitness.json (strength 0 switches it off).
- Server-owned, saved in characters.json (same atomic/.prev path, still version 1) and sent to the client in vitals() only for the Tab screen. Tests: test_server_items (fitter characters are winded and black out later, ratio matches exp), persistence drills (fitness survives torn files).
- Over-exerted slowdown (Dave): client pace x0.9 in state 1 (exertion.json over_speed_factor), no cap, running allowed; the server does not validate speed against a minimum, so a slower client cannot trip any check.
