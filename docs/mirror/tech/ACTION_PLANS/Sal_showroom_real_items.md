Best-practice suggestions:
1. **Idempotent seeding.** Give each showroom item a stable key (row name + index) and make the seed an UPSERT: spawn if the key is missing, leave it if present, refill if picked up. Do not delete-and-recreate (it flickers and loses items players moved). The admin button "respawn showroom" = clear all keys then seed.
2. **Do not save showroom items.** Regenerate them from showroom.json when an admin turns Admin mode on (one click after a restart). This avoids a world_items.json schema change (save changes need my approval) and keeps the save small. Exclude them from the despawn sweep and the world-item cap while they exist (answer to your question: no despawn).
3. **Admin and test-world only.** The server action checks the admin flag and a server setting `showroom_enabled` (off in a real shared world), because anything picked up becomes a real item in the economy. Log who seeded.
