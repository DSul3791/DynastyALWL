Headline: the server is hard-capped at 32 clients (terrain_server.gd:392, app_config.gd), runs all gameplay on one main thread with about 0.5 ms per player per second of budget at 1000 players, broadcasts dug/filled/flora_cut/tile_changed/water_changed to ALL peers, loops every peer in vitals/send/save, and has no per-player limits. All numbers marked "est." are unmeasured; step 0 (protocol-only bots plus per-RPC cost counters) must measure them. Dave answered (questions/ANSWERS.md scale-target, 2026-10-22 01:24): 1000 spread across the whole world, so layering is not phase one; keep a soft per-area cap as a safety valve, size the starter tile process for 200-300, and sharding by tile is the main scale-out path (SCALE_PLAN.md top section updated).
